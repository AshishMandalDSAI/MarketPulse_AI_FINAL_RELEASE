# MarketPulse AI — Methodology

## 0. Dataset-first: semantic column classification

Before any of the demo-dataset-specific methodology below applies, an
uploaded dataset goes through schema-agnostic semantic column
classification (`src/data_engine/column_classifier.py`), so this
platform is not limited to the NovaMart schema described in the rest of
this document. Each column is matched against generic alias vocabularies
(`config/column_aliases.py`) in three confidence tiers:

1. **Alias-exact** (confidence ≈0.95) — the normalized column name
   (lowercased, separators collapsed to spaces) exactly matches a known
   alias for a role, e.g. `"revenue"`, `"order date"`, `"google ads"`.
2. **Alias-fuzzy** (confidence ≈0.70–0.80) — the normalized column name
   contains, or is contained in, a known alias as a substring, guarded by
   a minimum alias length (4 characters) so short fragments like `"ig"`
   don't false-positive-match inside unrelated words like `"digital"`.
3. **Statistical fallback** (confidence ≈0.40–0.55) — used only for date
   and revenue when no alias match exists at all: a column is guessed as
   a date if ≥85% of a sample parses as a datetime, and as revenue if it
   is a non-negative numeric column with meaningful variance (coefficient
   of variation > 0.05) and isn't a near-constant flag/ID-like column.

**Confidence-based confirmation rule:** a guess at **HIGH** confidence
(≥0.80) is auto-selected with no user action. A guess at **MEDIUM**
(0.55–0.79) or **LOW** (<0.55) confidence is surfaced to the user with
its confidence level, but is **never auto-applied** — it is only used if
the user explicitly confirms it (`accept_suggested`) or supplies an
explicit override. This is enforced structurally, not just by UI
convention: `ColumnMapping.clear_unconfirmed_low_confidence()` resets any
unconfirmed sub-HIGH guess back to unmapped before standardization ever
runs, and the freed column is reclassified by its plain dtype (as a
generic numeric "control" or categorical "dimension" column) rather than
being force-mapped or dropped. This rule is covered directly by
`tests/test_dataset_first_platform.py` (e.g.
`test_weak_guess_not_auto_used_as_revenue`,
`test_confirmed_roles_survive_clear_low_confidence`).

## 1. Dataset

The dataset is entirely **synthetic**, generated by `src/data/generate_dataset.py` for a fictional
e-commerce company, "NovaMart." It covers 208 weekly observations (~4 years). The data-generating process
deliberately encodes:

- **Seasonality**: an annual sine-wave cycle plus a slow secular growth trend.
- **Holidays**: recurring festive/sale weeks with a revenue and promotion-spend lift.
- **Marketing carryover (adstock)**: each channel's spend has a documented per-channel geometric decay
  rate, so this week's spend continues influencing revenue in subsequent weeks.
- **Diminishing returns (saturation)**: each channel's adstocked spend passes through a Hill saturation
  function before contributing to revenue, so extra spend yields progressively smaller effects.
- **Price, competitor, and economic effects**: revenue responds negatively to price and competitor-index
  increases and positively to a rising economic index.
- **Noise and anomalies**: multiplicative residual noise plus four controlled shock weeks (two negative,
  two positive) to mimic real-world one-off events (e.g., stockouts, viral moments).

This means the dataset has genuine, recoverable statistical structure for the MMM to find — it is not pure
random noise, but it is also not real company data, and no business conclusions from this project should be
read as describing an actual company.

## 2. Marketing Mix Modeling Approach

### 2.1 Adstock (carryover)
Geometric adstock: `adstock_t = spend_t + decay * adstock_{t-1}`. Decay rates are selected per channel via
a documented grid search (`DECAY_GRID` in `src/models/adstock.py`) that maximizes univariate correlation
with revenue — a standard, computationally light simplification appropriate for a project of this scale.

### 2.2 Saturation (diminishing returns)
Hill function: `saturation(x) = x^s / (k^s + x^s)`, where `k` is the half-saturation spend level and `s`
controls curve steepness. Chosen over a log-transform because it passes through the origin and has an
interpretable half-saturation parameter.

### 2.3 Regression
Ridge regression (L2-regularized linear regression) on standardized features — chosen for stability with a
modest number of weekly observations (208) relative to the number of engineered features (8 channels + 5
controls), and because `statsmodels` was not installable in the offline development sandbox used to build
this project (see Limitations). Ridge is a standard, well-understood, and easily explained choice for MMM
of this scale.

### 2.4 Train/test split
**Time-aware (chronological) split** — the most recent 20% of weeks are held out as test data. The series
is never shuffled, since shuffling a time series before splitting leaks future information into training
and produces artificially inflated accuracy.

### 2.5 Model comparison & selection
Three models are compared: (1) baseline — raw spend + controls, (2) adstock — adstocked spend + controls,
(3) adstock + saturation — fully transformed spend + controls. The final model is **not** selected by R²
alone: the more complex model is only preferred if it also matches or improves out-of-sample RMSE and MAPE
within a small documented tolerance (see `marketing_mix_model.py::run()`).

## 3. Channel Attribution

Contribution is estimated via **leave-one-channel-out ablation**: for each channel, its transformed spend
feature is zeroed out, the model re-predicts revenue, and the drop from the full-model prediction is taken
as that channel's estimated incremental contribution. This is more interpretable to a business audience
than raw regression coefficients and is clearly labeled as **model-estimated**, not observed or audited.

## 4. Budget Optimization

`scipy.optimize.minimize` (SLSQP) maximizes predicted revenue subject to a total-budget equality
constraint and per-channel min/max bounds. Because adstock depends on spend history, the optimizer treats
recent weeks' carry-in as fixed and optimizes a single representative week's re-allocation — a documented
simplification appropriate for a weekly budget-reallocation recommendation tool.

## 5. Forecasting

A deliberately simple Ridge regression on a linear trend + 52-week Fourier harmonics, chosen for
reliability and interpretability over a more complex (and, with ~200 observations, likely unstable) model
such as ARIMA or a neural forecaster.

## 6. Limitations

- Per-channel adstock/saturation parameters are selected via univariate correlation search rather than a
  full joint optimization across all channels simultaneously (computationally expensive at project scale).
- The dataset is synthetic; conclusions do not describe a real business.
- `statsmodels` was unavailable in the offline sandbox used to build this project, so Ridge regression
  (scikit-learn) was used instead of an OLS/statsmodels-based approach. Ridge is a standard and defensible
  substitute for MMM at this data scale.
- The budget optimizer's "representative week" simplification does not fully model multi-week dynamic
  budget-pacing effects.
